# 产品范围

## 当前迭代

EasyLens 首先服务于英文阅读：用户从托盘或通过 Ctrl+Alt+L 唤出眼睛，眼睛始终贴近鼠标；中心落在英文单词上时显示中文。若当前选区包含这个焦点词，优先翻译完整选区。Esc 隐藏。中文等非英文内容不进入翻译流程。

当前正式可运行入口是 Electron，已在本机 Linux 上完成安装、启动、测试和打包验证。图标驻留托盘，不创建常驻主窗口；眼睛是透明、置顶、不接收鼠标事件的窄窗口，中心保持透明，翻译卡在眼睛下方或上方展开。原 macOS 15+ Swift 工程保留在 `Sources/EasyLens/`，作为交互、英文门控和选区行为的参考，不再是默认构建入口。

屏幕文字由 Electron `desktopCapturer` 截取光标附近画面，Tesseract.js 使用随包英文数据做 OCR；拍照前会短暂隐藏翻译卡。Linux 还会短暂隐藏真窗口以避免置顶透明窗口遮住目标文字；macOS/Windows 不隐藏也不调暗眼睛窗口，直接依赖眼睛中心的透明孔完成拍摄，避免 WindowServer 反复重建窗口层级造成闪烁。默认翻译来源是随包的 ECDICT 英文词条子集，完全离线：单词查词并做基本词形还原，长选区按行/词释义，不宣称是通顺的机器翻译。托盘设置中可选择 DeepSeek，配置 HTTPS 接口地址、模型和 API Key；远端只接收待译文字，不接收截图。密钥保存在 `~/.easylens/deepseek-api-key`（目录 `0700`、文件 `0600`），非敏感设置保存在 `~/.easylens/settings.json`。未保存密钥时不能切换到 DeepSeek，选择本地来源时不会发起网络请求。

Linux 没有 Accessibility 的跨应用选区几何。完整选区优先读取 PRIMARY（Electron `clipboard` 的 `selection` 类型，必要时回退到 `wl-paste`、`xclip`、`xsel`），其次使用近期剪贴板提示；只有文本通过英文门控且包含当前焦点词时才按选区翻译，否则退回单词。这个回退能覆盖常见终端和编辑器，但无法确认指针是否真的落在高亮区域内，可能把陈旧选区误判为当前选区。识别与翻译异步进行；未命中缓存的远端请求若超过短暂等待时间，显示中性的“正在转译”卡片，翻译成功时眼睛内圈与眼珠纹路才变黄。以上是已实现并部分验证的工程路径，不意味着所有桌面环境、第三方应用和字体都已验证。

## 当前边界

- 只在 Linux 桌面上验证了 Electron 入口；macOS/Windows 的 Electron 构建尚未验证。原 Swift 程序仍需要 macOS 15+、Xcode 16+ 和系统权限，保留为参考实现。
- OCR 精度低于 macOS Vision；复杂字体、低分辨率、暗色界面、斜体和多列排版可能定位偏移或漏识别。
- 本地长选区翻译是逐行/逐词回退，不保证语法通顺。需要完整译文时应配置 DeepSeek；目前唯一的远端翻译提供方是 DeepSeek。
- 完整选区没有辅助功能命中几何，PRIMARY/剪贴板回退可能误判；不可用时退回单词。
- 屏幕捕获在 Wayland 下依赖 PipeWire/portal，黑屏时优先使用 X11；托盘图标可能需要桌面环境的 AppIndicator 扩展。
- 不持久化截图；只有显式设置 `EASYLENS_DEBUG_CAPTURE=1` 时才把最近一帧写到系统临时目录用于诊断。
- 当前是本地开发构建；正式发布签名、公证、安装包升级和自动更新尚未实现。
- 花纹、Logo、人物等识别类型属于后续探索，不据此预设框架。

工程结构与验证记录见 [electron.md](electron.md)；macOS Swift 原型归档见 [engineering.md](engineering.md)。
