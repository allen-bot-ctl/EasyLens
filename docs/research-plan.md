# 调研与实验计划

本页是后续工作的起点，不构成技术选型结论。

调研中的文档放在 `tmp/docs/`，轻量验证脚本放在 `tmp/scripts/`。Git 只保留目录占位文件，忽略其中的工作内容。结论定稿时，提炼可复核的证据、限制和决策，归档到正式 `docs/`；不直接把未经整理的草稿当作工程真源。

## 建议顺序

1. 明确首发平台与关键体验：快捷键、窗口遮罩、覆盖区域取像和结果展示。
2. 对候选方案做小规模端到端实验，测量唤起、取像、OCR、语言判断和翻译的实际表现。
3. 用纯英文、纯非英文、混排、低清晰度和空白区域验证跳过规则与失败路径。
4. 复核权限、隐私、离线需求、性能、安装体积和分发约束。
5. 在证据足够后记录选型决定，再建立正式工程和持续验证流程。

## 每项调研或迁移实验记录

- 问题与假设：要证明什么，成功和失败如何判定。
- 环境与版本：平台、依赖、样本和复现步骤。
- 结果：可观察证据、耗时或准确度，以及已知限制。
- 结论：采用、继续验证或放弃的理由；标出未解决问题。

实验产物与正式工程须明确区分。只有通过目标用户路径验证、边界审查和选型决定的方案，才进入正式架构文档。
