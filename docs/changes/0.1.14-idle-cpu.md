# 0.1.14 眼睛收起后不再占 CPU/GPU

老板反馈（2026-11-22 23:26 ET）：很久没用 EasyLens，活动监视器里 EasyLens Helper (GPU) 35% CPU、29.6% GPU，Helper (Renderer) 27% CPU，一直不降。

## 根因（mind 读代码确认）
1. `renderer/lens-scheduler.js` 的 rAF 循环一旦启动就永不停：`tick()` 每帧无条件 `requestNextFrame()`，suppressed 时也续帧；`stop()` 存在但全工程没有任何地方调用。
2. 眼睛窗口 `backgroundThrottling: false`，所以 `hideLens()` 把窗口藏起来后，渲染进程仍以 60fps 跑 `draw()`（呼吸动画每帧 clearRect + 重绘），每帧都提交给 GPU 进程合成 → 就是截图里的 Renderer + GPU 占用。
3. `hideLens()` 里还调了 `suppressLens(false)`，等于收起时又给渲染进程发了一次唤醒。
主进程 16ms 的 `tick` 收起时已经 `stopTick()`，不是问题来源。

## 锁定改法
| 状态 | 渲染进程帧率 | 做法 |
|---|---|---|
| 眼睛收起（hideLens 后、启动后未显示） | **0 帧** | main 新发 `lens:sleep`，renderer 收到后 `scheduler.stop()`；`hideLens()` 不再调 `suppressLens(false)` |
| 眼睛显示、鼠标在动或正在识别/翻译 | 60fps | 不变 |
| 眼睛显示、鼠标静止 ≥ 1.5 秒且没有在识别 | ≤ 10fps | 呼吸动画降帧（用 setTimeout 100ms 代替 rAF），鼠标一动立刻回 60fps |
| 眼睛重新显示 | 立即回 60fps | 沿用 `resumeLensRenderer()` → `ensureRendering()`，第一帧在 showInactive 后 100ms 内画出 |
| 被截屏抑制（suppressed） | 不画但保持循环 | 维持现状，修 0.1.x「眼睛消失」bug 的不变式不能破 |

`backgroundThrottling: false` 保持不动（截屏期间需要）。卡片窗口的 pulse 动画只在 loading 行显示时存在，不改。

## 验收条目（契约测试，CI 两种芯片都跑）
- P1 渲染进程测试钩子暴露帧计数；显示后 hideLens，之后 3 秒内帧数 = 0。
- P2 显示、鼠标静止 3 秒（第 1.5 秒后开始计），1.5 秒内帧数 ≤ 16。
- P3 再次 showLens 后 200ms 内帧计数恢复增长；鼠标移动时 1 秒帧数 ≥ 45。
- P4 截屏抑制再恢复，眼睛照常出现（原有回归用例全过）。
- P5 lens-scheduler 单测：stop 后不再请求帧；ensureRendering 后恢复。
- M1 老板真机：升到 0.1.14，眼睛收起放 1 分钟，活动监视器里 EasyLens Helper (GPU) 和 (Renderer) 的 %CPU 都 < 1%。
