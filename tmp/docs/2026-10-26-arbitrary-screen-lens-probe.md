# 任意屏幕位置识别框实验

日期：2026-10-26。状态：本机交互原型，尚非正式产品实现或技术选型。

## 使用

在仓库根目录运行：

```bash
zsh tmp/scripts/run_local_lens_probe.sh
```

运行后菜单栏出现 `EL`，识别框初始隐藏。按全局快捷键 `⌃⌥L`（Control + Option + L）唤醒；将鼠标移到屏幕上任意目标文字附近，识别框跟随鼠标；停稳约 1 秒后，在指针周围受当前屏幕边界约束的上下文区域取像。OCR 只选与初始小框相交或紧邻续行的文字，再把可见框调整到选中文字的范围。按 `Esc` 隐藏识别框；隐藏期间不占用 `Esc`。再次按 `⌃⌥L` 可重新唤醒。菜单栏 `EL` 提供显示和退出入口。

文本自适应框选是默认行为。也可按 `⌃⌥=` / `⌃⌥-` 以 160 点为单位调整起始框宽度；加 `⇧` 改为以 80 点为单位调整高度。改变尺寸后停稳约 1 秒重新识别。`--lens-size=宽,高` 可设置本轮实验的起始尺寸。手动尺寸用于定位与兜底，识别后的橙色边框表示最终文字范围；OCR 单独保留蓝色框。

默认仅显示识别文字及英文候选片段。加上 `--local-translate` 后，英文片段由 macOS Translation 在设备端译为简体中文，译文放在框外可滚动、可复制的结果窗中，避免遮住源文字；首次使用需先运行 [本地翻译实验](2026-10-26-local-translation-probe.md)准备系统语言包。屏幕图像只在内存中处理，不保存截图，不调用云端 LLM 接口。初次运行时，macOS 可能要求授予屏幕录制权限。此脚本不创建目标文字测试窗口；被识别内容来自屏幕上已有的任意应用。

同时只允许一个实验实例运行。若已有菜单栏 `EL`，先退出旧实例再重新启动脚本；否则第二次启动会打印错误并退出，避免两个识别框互相被 OCR 读入。

```bash
zsh tmp/scripts/run_local_lens_probe.sh --local-translate
```

## 本机验证

- 在 macOS 15.7.7、Intel Core i7-8569U、双显示器环境，脚本编译通过；`--once --quiet-text` 方式完成一次任意屏幕位置取像和 `.fast` OCR。
- 交互运行时，通过系统按键事件实际触发 `⌃⌥L → Esc → ⌃⌥L`，依次观察到 `LENS_SHOWN`、`LENS_HIDDEN`、再次 `LENS_SHOWN`；每次显示期间均成功注册 `Esc`，隐藏时解除注册。
- 两次交互取像分别约 288/93 ms，`.fast` OCR 分别约 66/64 ms。取像区域当时没有通过英文候选门禁的文本；这些数据只证明当前机器上的调用链可运行，不能代表真实文字场景的识别率或稳定延迟。
- 全程 `CLOUD_CALLS=0`，未进入 LLM 接口。
- 语言包安装后，`--local-translate` 在真实屏幕区域完成 OCR → 英文门禁 → 本地英译中；另一个非英文区域保持 `englishSegments=0`，未触发翻译。测量与限制见 [本地翻译实验](2026-10-26-local-translation-probe.md)。

## 待验证

当前自适应仅按英文文字行的几何关系工作，尚未处理双栏、相邻聊天气泡、非文本特征等复杂区域。字号、窗口层级、跨屏坐标、滚动或频繁移动、屏幕录制授权流程以及英文门禁的误判率，还需使用真实应用内容持续测量。全局快捷键目前硬编码，与其他应用冲突时仅在终端打印注册错误；正式产品需要可配置和可见的冲突提示。
