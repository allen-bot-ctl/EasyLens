# 双段选区在鱼眼游走时退回单词：定位与复测

日期：2026-10-27。性质：Tabbit/Claude 页面上的临时实验记录，尚非跨应用保证。

## 复现与原因

用户选中相邻两段，第一段以 `Good morning!` 开头，第二段以 `What can I help` 开头。Tabbit 的 `AXSelectedText` 长度为 403，覆盖两段；`AXStringForTextMarkerRange` 也返回 403 字符，但同一标记的起止索引是 `0..325`，`AXBoundsForTextMarkerRange` 只落在第二段的 736×89 区域。原逻辑直接信任标记几何：在第一段会报告范围外，随后 `knownMissTexts` 还会压掉完整的 403 字符选区，转入单词翻译。

另一个独立漏判在视觉核对：原逻辑要求鱼眼中心几乎精确进入单词字形框（归一化距离不超过 0.05）。指向高亮行的词间空白或行边缘时，OCR 仍能读到该行，但焦点索引被置为无效；临近换行处，最近的字形甚至可能属于下一行。任一核对失败就立即清除选区模式，让单词缓存结果显示出来。辅助功能查询偶尔超时也有同样效果。

## 本次实验调整

1. 仅当标记文本与 `AXSelectedText` 一致、且可读取的标记索引跨度与选中 UTF-16 长度一致时，才让标记几何参与命中或排除；否则用当前完整选区文本做视觉核对。
2. 单词焦点与选区焦点分开：后者先找鱼眼中心实际落入的 OCR 行，再取该行最近的词作连续文本匹配。行框只按行高加少量边缘容差，避免跳到上下相邻的紧凑行。
3. 先用焦点两侧各两词核对；不足时再扩大到三词。保持至少三词、12 个英文字母的连续证据。
4. 已确认的选区遇到一次辅助功能空结果时，只在一秒内、且当前 OCR 行仍匹配同一选区时暂留整段模式并快速重查。新的单词或页面内容不匹配就立即回到非选区模式；临时保留不会自行续期。

## 验证范围

- 在同一张实际双段高亮截图上抽样 25 个焦点：22 个位于高亮文字行内的点全部匹配完整选区；3 个超出末行文字右边界的点均未提升为选区。上方未选中的 `morning` 气泡、`Reply` 按钮、段间空白和侧栏搜索也未提升。
- 运行中的探针分别固定在第一段 `October` 附近、第二段文字上，均记录 `SELECTION_HIT ... length=403`、`SELECTION_TRANSLATION ... resolved=yes`；第一段的屏幕截图确认卡片展示完整两段中文。固定在未选中的 `morning` 气泡上时，记录单词翻译，没有 `SELECTION_HIT`。
- `swiftc` 编译通过。现有 `check_selection_focus_cases.py` 在 `merged focus only` 用例失败；对本次修改前的 Git 版本单独编译复查，也得到同样的 `promotes=false`，因此不是本次回归。该用例与当前“至少两词核对”的行为不一致，需单独整理测试期望。

上述抽样不等于用户真实游走的成功率；仍需在更多页面、字体缩放和局部选区中观察。`AXSelectedText` 与标记几何互相矛盾的情况不能直接用标记范围裁决。
