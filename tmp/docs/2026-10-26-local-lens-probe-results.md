# EasyLens 本地取像与 OCR 小实验

日期：2026-10-26。状态：本机受控样本的历史结果，尚非正式产品架构或性能承诺。实验在“得到可提交云端的英文 OCR 文本”处停止，网络请求数为 0。当前面向任意屏幕位置的交互原型及快捷键验证见 [任意屏幕位置实验](2026-10-26-arbitrary-screen-lens-probe.md)。

## 实验范围

脚本：[local_lens_probe.swift](../scripts/local_lens_probe.swift)，仅用于历史受控样本实验。当前入口已改为任意屏幕位置的交互原型；如需复核本次历史实验，可单独编译该脚本。原运行命令已不再对应本节结果。

脚本只使用 macOS 自带的 AppKit、ScreenCaptureKit、Vision 和 NaturalLanguage。它创建一个受控文字窗口和一个覆盖在文字上的不透明遮罩，依次模拟移动到英文、中文、法文和中英混排行，每次停稳 1 秒后取区域图。比较遮罩包含与排除后的结果，并分别运行 Vision `.fast` / `.accurate` OCR、片段级英文门禁。它不保存截图，不调用云端接口，也不读取系统剪贴板。

运行机器：macOS 15.7.7、Intel Core i7-8569U；本次结果来自 2× 缩放的显示器。ScreenCaptureKit 的首次屏幕录制授权和不同机器、不同显示器的结果仍需单独验证。

## 最后一次完整运行的观察

- 遮罩参与捕获时识别到 `EASYLENS MASK`；排除该遮罩窗口后识别到底层英文。脚本还检查每次截图中受控窗口的彩色标记，标记不可见就拒绝 OCR。
- 英文区域连续 20 次均识别到预期文字，英文门禁均通过。`READY_FOR_CLOUD_TEXT` 输出的是 OCR 片段，脚本随后停止在云端调用之前。
- 法文区域 5 次均识别到预期文字，英文门禁均跳过。
- 中英混排区域 5 次均识别到 `Hello world`，英文片段通过；中文部分在 OCR 中有时被误读成拉丁杂字符，当前分句门禁没有提交这部分。
- 纯中文区域确有深色文字像素，但 `.accurate` 5 次均返回空结果；`.fast` 会把部分字形误读为拉丁杂字符。该样本 5 次均被门禁跳过，但不能据此证明其他中文画面不会误判为英文。

| 受控样本 | 次数 | `.fast` 预期文字命中 / 英文门禁通过 | `.accurate` 预期文字命中 / 英文门禁通过 | 区域取像 p50 / p95 | `.fast` OCR p50 / p95 | `.accurate` OCR p50 / p95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 英文 | 20 | 20 / 20 | 20 / 20 | 128 / 143 ms | 37 / 56 ms | 446 / 470 ms |
| 中文 | 5 | 0 / 0 | 0 / 0 | 121 / 164 ms | 33 / 44 ms | 409 / 429 ms |
| 法文 | 5 | 5 / 0 | 5 / 0 | 149 / 413 ms | 30 / 44 ms | 413 / 460 ms |
| 中英混排 | 5 | 5 / 5 | 5 / 5 | 125 / 132 ms | 32 / 36 ms | 298 / 324 ms |

这些是同一批静态 UI 文字的重复测量；5 次样本的 p95 基本接近最慢一次，不能当成稳定尾延迟。区域取像列包括本实验的彩色标记检查。不同轮次存在明显波动，例如一次英文取像 p95 为 374 ms；不能只引用最好的那轮。OCR 执行和测试窗口都在同一原型进程里，尚未测试正式客户端的线程隔离、持续拖动、真实屏幕字体和系统负载。

## 发现的捕获风险与修正

一次诊断运行中，测试窗口被其他应用盖住，显示器区域捕获取得了非测试内容。该次结果作废，临时图片已删除。脚本现将目标窗口保持在遮罩下方的较高层级，并在每次 OCR 前检查目标窗口的彩色标记；首次还要求排除遮罩后必须识别到受控英文。标记检查只是本实验的保护措施，不能作为真实产品的目标内容判定方式。

## 到云端接口前的结论

本机在受控英文样本上，区域取像加 `.fast` OCR 的典型耗时约 165 ms（两个中位数之和），`.accurate` 约 574 ms；这不是完整交互耗时，也不是并发或真实桌面场景的保证。镜头停稳 1 秒、取像、英文门禁及过期结果丢弃的状态机仍需交互原型验证。

目前可作为云端文字翻译输入的本地输出示例：`The quick brown fox jumps over the lazy dog`、`Hello world`。真实产品应从 OCR 结果而非样本文字构造请求；当前脚本正是这样输出，且完全不含 LLM 接口代码。

下一轮本地验证应扩大文字样本：其他应用与字体、不同字号和对比度、中文/日文/韩文、短英文、代码、网址、滚动内容以及遮挡；同时测移动中的 UI 帧率和从停稳到文本可用的端到端 p95。只有英文门禁误报率和真实桌面取像稳定性可接受，才值得接入云端翻译对照实验。
