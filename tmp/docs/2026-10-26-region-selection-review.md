# EasyLens 选区策略：外部产品对照与窗口分层实验

日期：2026-10-26。状态：临时调研与本机原型结论，尚非正式产品或技术选型。

## 要解决的问题

EasyLens 的首个目标是让用户在任意屏幕位置快速指定英文内容，并得到完整的中文译文。此前连续修正 OCR 行距、图标伪文字和相邻状态行，说明“从一次 OCR 行框直接猜唯一段落”缺少上层边界；单张截图调阈值也无法证明跨页面有效。本轮把**目标窗口、指针附近的文字、用户显式区域**分成不同层级，避免把它们混为一种选区。

## 外部产品的公开能力与可借鉴点

| 产品 / 系统 | 可核对的公开事实 | 对 EasyLens 的启示 |
| --- | --- | --- |
| [iShot](https://www.better365.cn/h-col-106.html) | 分别提供光标下窗口、手动区域、多窗口截图，并可在截图区域上调用 OCR；未公开其窗口判定或子区域算法。 | 窗口是可靠的上层范围候选，不能据此推断它能找出窗口内的某段文字。 |
| [Bob](https://bobtranslate.com/guide/quickstart/ocr.html) | OCR 由用户框定区域；产品提供智能分段，并明确提醒多栏文档宜每次只选一栏。[翻译指南](https://bobtranslate.com/guide/quickstart/translate.html)区分可复制的划词与不可复制内容的截图翻译。 | 即使有段落算法，输入区域仍需可控。自动选区应允许用户纠偏，尤其在多栏中。 |
| [TextSniper](https://textsniper.app/blog/how-to-turn-image-to-text-on-your-mac) | 快捷键后拖出屏幕区域，再对该区域 OCR。 | 用户意图由显式区域表达；不能只以 OCR 行的文字量推测意图。 |

| macOS | [Quartz Window Services](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo%28_%3A_%3A%29?changes=_9&language=objc)可列出屏幕窗口及边界；[Vision](https://developer.apple.com/documentation/vision/recognizing-text-in-images?changes=lates_7)返回文字与行框；[Accessibility](https://developer.apple.com/documentation/applicationservices/1462077-axuielementcopyelementatposition?changes=_6)可尝试按位置命中元素。 | 系统提供不同粒度的线索，须验证坐标、时延与可靠性，不能把其中任一项视为完整的语义选区。 |

以上是功能与接口事实；“分层组合”是我们的设计推论，不是对其他产品内部实现的猜测。

## 本轮取舍

1. **窗口作搜索边界。** 自动模式先查找悬浮镜头下方、指针所在的前台普通窗口，并与原局部扫描区域取交集。若指针落在菜单、特殊层、桌面或窗口查询失败，沿用显示器内局部扫描。手动区域模式完全按用户给定矩形取像。窗口只限制跨应用误选，不自动成为最终黄框。
2. **镜头范围与指针共同表达目标。** OCR 后仍以相邻文字行组成候选块。默认大小的镜头按指针焦点取单块；用户放大镜头后，实质覆盖的多个块都进入选区。放大镜头却没有覆盖块时仍用指针附近最近的块作回退；没有足够近的块就不自动翻译。删除旧版“英文字符最多的块优先”回退，避免旁边的大段正文抢走小词或标题。
3. **辅助功能暂不参与决策。** 本机可访问 AX，但对当前应用的数个位置探测，有命中元素的公布矩形不包含查询点。AX 元素可能是整个网页组，也可能因应用实现而失准；待采样更多应用，并验证可靠性与耗时后，再作为有条件的证据。不能要求它覆盖图片、视频、画布和不完整的辅助功能树。
4. **不宣称唯一正确的自动选区。** 多栏、气泡与同样式相邻段落存在真实歧义；保留现有 `⌃⌥M` 手动区域与尺寸调整作为明确纠偏路径。以后若增加候选切换，应复用同一次截图和 OCR 结果，避免重复取像。

## 补充实验：一个镜头覆盖多个段落

用户反馈指出：扩大的蓝色镜头同时覆盖状态段和正文段时，旧算法仍强制只取指针最近的一个文字块。这不是 OCR 不能识别两段，而是选区决策丢掉了用户通过镜头大小表达的范围意图。

原型在**用户放大镜头后**判断哪些文字块有一行的垂直中心落在镜头内部，且该行与镜头的水平重叠达到较短一方宽度的 60%。满足条件的块全部进入选区；仅擦到边缘的不进入。每块的其他行可延伸到镜头外，由同次扩展扫描的 OCR 补齐。所选文字块按屏幕阅读顺序形成独立翻译片段。默认大小的镜头仍优先取指针附近的单块，避免状态行与正文意外合并；放大镜头但没有覆盖块时，也回退到指针附近的单块判断。手动区域仍严格使用实际矩形。

在用户这张含两段的截图上，按蓝框近似尺寸 1038×376 像素离线重放，选到 `Checking...` 和 `Morning...` 两个独立英文片段；把镜头缩到仅覆盖正文或状态行，则分别只取一段；气泡 `morning` 单独覆盖时只取该词；空白处返回 0。之前单块样本用默认大小重放仍各自只取一块。截图里的蓝框遮挡了长句中间几个字，因此这张**带遮罩的截图**只能验证选区，不能用来评价实时 OCR 完整性；实时取像会排除 EasyLens 窗口。

另用无遮挡的临时双段窗口跑通实时取像和本地翻译：OCR 得到两句完整英文，生成 2 个英文片段，Translation 返回并展示 2 个中文片段，用时约 493 ms；临时窗口随后关闭。窗口边界查询约 30–36 ms，但这次窗口范围没有缩小扫描区，因此不能以这个样本证明窗口裁剪效果。仍需在双栏、相邻控件与不同应用的多段布局上做统一验收。

## 实现与验证

- 原型修改在 `tmp/scripts/screen_lens_probe.swift`：窗口查询排除 EasyLens 自身，选中指针下方最前面的普通窗口；只在交集有效时缩小扫描区。日志增加 `window_scoped`、`window_reduced_scan`、`window_lookup_ms`，不记录窗口名、源文字或截图。
- 用先前的无遮挡聊天截图复跑：默认镜头分别可选下方两行正文、上方状态行与 `morning` 气泡；两行正文组成一个翻译片段。在无目标的空白点返回 0 行、0 英文片段。仅验证这些离线样本，不等同于多栏覆盖率。
- 本机创建并关闭一个 500×260 点的临时英文窗口，在主屏和副屏各做一次一键取像：两次均出现 `window_scoped=true`、`window_reduced_scan=true`，实际扫描区为 500×288 点，得到 1 行、1 个英文片段；窗口查询约 29 ms 与 36 ms。窗口的外框包含标题栏，所以扫描高度可比内容高度大。
- 主屏又跑了一次英译中完整链路：窗口查询 25.6 ms、取像 360.2 ms、OCR 106.7 ms、本地 Translation 437.0 ms，1 个片段请求对应 1 个译文响应，未进行云端调用。均为少量本机样本，且另有 1 秒停稳门槛；尚不能外推尾延迟或跨 App 准确率。

## 下一轮统一验收，而非继续按截图改阈值

固定一组覆盖浏览器单栏与双栏、聊天气泡、状态行、短词、窗口交叠、菜单、桌面、多显示器、白底与深底的样本。每个样本标记指针点、目标框和应翻译的文本；分别统计目标命中、跨块混入、文本完整、无目标时误触发及从停稳到结果的时延。与本轮纯视觉基线对比，若窗口边界不能降低跨窗口误选，或使合法的菜单/浮层目标遗漏，就撤回默认启用。辅助功能线索只有在更多应用中证明位置和文本对应可靠时才加入。
